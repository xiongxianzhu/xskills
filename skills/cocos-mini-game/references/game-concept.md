# 主题到玩法方案

## 方案数量

根据趋势调研输出 2–3 个可明显区分的方向。不要只替换角色皮肤；方案之间应在核心动作、节奏或成长结构上不同。

## 设计约束

- 首版聚焦 2D、IAA、微信与抖音双端。
- 优先考虑单手操作、短局、快速理解和可重复游玩，但根据主题证据调整。
- 核心循环先于外围系统；没有验证玩法前不规划商城、大量活动或复杂社交。
- 广告点必须来自自然需求，例如复活、结算翻倍或可选加速，不能强迫观看才能继续基本游戏。
- 考虑竖屏/横屏、单局时长、目标年龄层、素材数量、关卡产能和实现风险。

## 评分维度

使用 1–5 分做相对比较，不伪装成精确市场预测：

| 维度 | 问题 |
| --- | --- |
| 主题契合 | 主题是否自然支持核心动作与反馈？ |
| 市场证据 | 近期是否存在可核验需求或相邻成功案例？ |
| 差异化 | 是否能一句话说明与同类产品的不同？ |
| 首版成本 | 小团队能否快速完成可玩闭环？ |
| 双端适配 | 是否依赖某个平台独有且不稳定的能力？ |
| IAA 适配 | 是否有不伤害体验的自愿广告点？ |
| 内容产能 | 关卡、数值和素材是否可持续制作？ |

## 停止点

仅在方向未定且用户未授权自行选择时等待；只暂停依赖玩法决策的 PRD、代码与素材。已给出明确玩法或授权采用推荐方案时，直接进入请求的下一阶段；仅策划请求止于提案。
