## 验收（Gate）

按明确验收标准自检；复杂或高风险任务按需独立审查，不强制另找 Agent。

| 角色 | 说明 |
| --- | --- |
| 执行 | 主 Agent 按工作流程产出 |
| 验收 | 根据本次改动选择相关测试或规范检查；需要时另作只读审查 |

验收不通过时：带着具体错误信息修正，进入下一轮（见下方停止条件）。

## 停止条件

Loop 或多次重试时必须设硬上限，避免无限烧 Token：

| 类型 | 示例 |
| --- | --- |
| 迭代次数 | 最多 3 轮 |
| Token / 成本 / 时间 | 仅采用用户或工具已明确配置的上限 |

检查通过即结束，迭代次数是上限而非目标。适用上限触达或同一外部阻塞重复出现时，停止该部分重试，报告恢复条件并继续独立工作。

## 状态（可选）

长任务、跨会话续跑时，在 `references/STATE.md`（或项目约定路径）记录：

- 目标与当前进度
- 已通过 / 未通过的验收项
- 待人工决策的问题

仅在启用状态记录的长任务中读取并更新 STATE；普通单次任务不创建状态文件。
