# 专业自然的中文技术写作

目标是让读者顺畅地理解事实、操作与取舍。这里的“去 AI 味”是编辑要求，不是作者身份判断，也不以 AI 检测器分数或“保证通过检测”为验收标准。

## 作者口吻

默认像一位认真解释问题的技术作者：用词准确，表达自然，结论有依据。无需假装聊天，也不把文章写成产品介绍或会议汇报。

- 有作者样稿时，先看句长、段落节奏、术语习惯、第一人称和标点，再沿用适合本篇的特征。样稿用于匹配文风，其中的经历、数据和评价不自动成为新文章的事实。
- 没有样稿时直接采用默认口吻，不要求用户先提供个人经历。正文可以没有“我”，仍能通过选择理由和适用边界体现判断。
- 保留材料里真实、具体、影响理解的细节和偏好。不要把一次失败的具体原因压缩成“踩了不少坑”，也不要为了简短删掉测试条件。
- 第一人称经历须来自用户明确提供的材料；代理运行过一次测试，不等于作者长期使用过产品。基于资料得出的建议应写出依据，不替作者编造观点或感受。
- 长句交代条件与关系，短句给出结论或动作。按信息需要变化，不规定句长比例，不把每句话拆成一段，也不故意制造语病、错别字或口头禅。

## 一次重写与一次对照

将以下步骤纳入既有的最多两轮修订，不再开启独立循环：

1. **确认信息边界**：对照用户材料或已核验初稿，记住核心事实、数值、版本、条件、否定、来源、测试状态和有用的作者判断；区分修辞与事实。材料自相矛盾时按研究规则处理，不用润色掩盖。
2. **按段落重写**：定位下表中的具体问题，围绕该段要传达的信息调整句子和顺序。只有局部措辞有问题时只改局部；同段换过词仍空泛时，重新组织整段。已经自然的文字可保留。
3. **对照并定稿**：连读一遍，检查是否只是换了一批套话，是否新增或丢失了事实、条件、语气强度和受保护内容。修正剩余问题后保存最终稿，不展示中间推敲。

只调文风时，不开展无关研究或补写新观点。需要具体信息而材料没有时，缩小句子的承诺，或将影响结论的缺口明确列出；不能捏造数字使句子显得具体。

## 识别问题，再选择改法

以下是检查线索，不是词语黑名单。判断一处表达是否应改，要看它在当前段落中提供了什么信息。

| 问题 | 中文稿中的常见表现 | 编辑动作 |
| --- | --- | --- |
| 空泛开场与意义拔高 | “在飞速发展的时代”“这标志着全新范式”“为行业注入活力” | 从本篇实际问题、变化或结果写起；只有材料支持时才讨论更大影响 |
| 用形容词代替证据 | “强大、全面、高效”“无缝衔接”“显著提升体验” | 写清谁能完成什么操作、减少哪个步骤或受到什么限制；没有测量就不补造提升幅度 |
| 抽象名词与缺少主体 | “实现能力建设”“完成优化赋能”“进行了有效处理” | 明确执行者和动作，例如系统校验、服务返回、用户选择；已有明确含义的专业术语照常保留 |
| 冒充权威与推测填空 | “业内普遍认为”“数据显示”却没有对应资料 | 使用确实存在、直接支持结论的来源；未证实的判断降级或删去，不编机构、引文和共识 |
| 刻意制造转折或深意 | 连续使用“不是……而是……”“真正重要的是”“说句实话” | 直接陈述本段结论，保留有事实作用的对比、否定和纠错，不虚构反方或替代方案 |
| 机械节奏与形式完整 | 每段同样长，每节三个点，每项都是“加粗标签：一句解释” | 按因果和阅读顺序组织；真正的步骤、并列项和结构化对比仍用列表或表格，不凑数量 |
| 反复预告或复述 | “下面我们来看看”，标题下一句重复标题，文末再复述开头 | 删除没有新增信息的预告和重复，保留必要的回指；章节名称不必照抄模板 |
| 为了换词改变术语 | 同一对象轮流叫平台、引擎、中枢、生态 | 同一概念保持名称一致，必要的重复比不准确的同义替换更好 |
| 假装随意或有情绪 | “家人们”“真的绝了”“说人话就是”，连续短问短答或金句碎片 | 回到具体解释；保留作者确有的自然表达，不额外编造吐槽、惊讶或私事 |
| 聊天残留与强行收尾 | “好问题”“希望对你有帮助”“需要我继续吗”“未来可期”“你怎么看” | 文章直接讲内容，结束在最后一个有用信息处；互动只在有具体讨论点或用户要求时出现 |

## 不能删错的内容

- **确定程度**：合并“可能、也许、在一定程度上”等重叠限定，但保留有依据的“可能”“尚未验证”“仅在某环境测试”。不把相关性写成因果，不把一次结果写成稳定能力。
- **必要的负面信息**：保留真实缺陷、故障原因、不可用平台和风险提示。“不支持并发写入”是有效技术信息，不因存在否定句就删除。
- **真实比较**：用户确实需要选择的方案、产品差异和实际被排除的路径可以比较。删的是没有信息价值的陪衬方案。
- **术语、标点与文体**：中文引号、顿号、正常转折、必要的正式表达都可使用；不照搬英文标题大小写、英文引号和连字符规则。默认减少装饰性破折号；作者样稿中有明确用途的标点可保留。
- **代码与资料原文**：代码围栏、行内代码、命令参数、配置、JSON/YAML、完整提示词、引文、文章标题引述、URL 和引用标识保持原样。即使含有检查词，也不替换。用户另有修改要求时才单独处理这些内容，并验证语义。
- **既有排版**：文风修改不改主题、行内样式或复制逻辑。代码块继续保留原始换行，长行块内水平滚动，圆角不超过 2px。先完成文字定稿，再生成同源的 Markdown 与 HTML 交付。

## 中文改写示例

以下均为虚构的编辑练习，仅用于说明改法；右侧只使用左侧已给出的事实，不是任何产品能力声明。

### 把宣传语还原为操作

原文：这套强大而高效的校验机制，为数据质量提供了坚实保障。导入 CSV 前，系统会检查必填表头；缺少表头时返回 400。

改写：导入 CSV 前，系统先检查必填表头；缺少表头时返回 400。

核对：文件类型、校验时机和状态码都保留，删掉没有证据支撑的评价。

### 保留前提和不确定性

原文：值得注意的是，在本次 Linux 环境的测试中，开启缓存后接口耗时从 820ms 降到了 610ms。这充分展示了缓存机制的巨大潜力。不过，我们尚未测试 Windows，也没有测试高并发场景。

改写：本次 Linux 测试中，开启缓存后接口耗时从 820ms 降到 610ms。Windows 和高并发场景尚未测试。

核对：不新增百分比，不扩大平台覆盖，也不把有限测试包装为普遍结论。

### 用完整句子讲清取舍

原文：诚实地说，这不是要不要重试的问题，而是如何掌控重试。失败后最多重试 3 次，超过次数就停止并记录错误。有次数。有边界。有记录。

改写：失败后最多重试 3 次，超过次数就停止并记录错误。

核对：保留重试次数、停止条件和错误记录；不擅自改成“总共尝试 3 次”，因为首次尝试与重试不是同一计数。

### 已经自然的句子不强改

原文：这次只检查了网页预览，微信手机端还没测。

处理：保留。它已说明检查范围和缺口，不需要补“总体而言”“仍需持续优化”或编造一句个人感受。
