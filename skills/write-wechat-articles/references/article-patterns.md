# 文章类型与最小结构

选择能完成信息闭环的最小结构。以下条目是信息检查顺序，不是必须逐项照抄的文章目录；可按阅读需要合并章节。删除无关章节，不统一开头，不固定小标题数量。

## 实战教程

1. 目标与最终结果
2. 必要前提
3. 最短可执行步骤
4. 完整代码或命令
5. 高频失败原因与解决方式

只解释关键步骤。能用结果证明的内容，不重复讲原理。步骤需要编号时保留编号，不为去 AI 味拆散可执行顺序。

## 原理分析

1. 核心结论
2. 支撑结论的关键链路
3. 必要代码、流程或例子
4. 适用边界

不要扩展成术语百科或完整历史回顾。

## 故障复盘

1. 现象与影响
2. 关键证据
3. 直接原因与根因
4. 修复方案
5. 预防措施

只保留影响判断的定位过程，不写流水账。

## 工具或产品评测

1. 评测目标与测试条件
2. 关键能力与实际表现
3. 限制与使用成本
4. 适用和不适用场景
5. 选择建议（前文已讲清时省略）

不要复述厂商宣传。没有实测时改写为资料分析，不称为实测。

## AI 创作实践

1. 创作目标
2. 最终工作流
3. 关键设置和必要参数
4. 完整提示词
5. 结果差异与限制
6. 必要的版权或平台风险

不介绍注册、基础界面或通用概念，除非它们会改变结果。

## 提示词分享

1. 适用工具、模型与用途
2. 一个完整可复制的提示词
3. 可替换变量
4. 关键使用说明
5. 能力边界

不要逐句拆解提示词。只说明会显著影响结果的变量。

## 混合类型

一篇文章存在多种类型时，选择一个主结构，只从其他结构补充必要部分。例如，AI 音乐教程可以使用“实战教程”为主结构，再补充完整提示词和模型限制。

## 自然结束

各类型都可在结果、具体建议或适用边界讲清后结束。不要自动补一节“总结与展望”，也不固定提出互动问题。细则见 [natural-writing.md](natural-writing.md)。
