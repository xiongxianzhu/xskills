# 微信公众号文章写作

写专业自然、短而有用的文章。先核验，再提炼，用具体事实和清楚的取舍支撑结论。

## 开始前

先确定交付范围：仅文字润色或片段修改时，只读取自然写作规范与必要上下文，返回修改文本；用户要求修改已有文件时更新该文件。完整公众号文章交付才执行排版和四文件生成；仅排版时保留正文，仅读取排版、主题与相关检查项。以下资料和检查按该范围选择，不默认全部加载。

1. 新写或调整文章结构时读取 [references/article-patterns.md](references/article-patterns.md)；文字创作或润色时读取 [references/natural-writing.md](references/natural-writing.md)。有作者样稿时先识别其文风，样稿不是必需输入。
2. 需要排版交付时读取 [references/wechat-formatting.md](references/wechat-formatting.md) 和 [references/themes.md](references/themes.md)，确定格式与主题。
3. 新写或补充事实性内容时，读取 [references/research-policy.md](references/research-policy.md)。
4. 完稿后按 [references/quality-checklist.md](references/quality-checklist.md) 检查与当前范围相关的项目；通过即结束，最多两轮修订，不为凑轮次重写。
5. 生成 `wechat.html` 时，以 [assets/wechat-preview-template.html](assets/wechat-preview-template.html) 为页面外壳，不重新设计复制逻辑。

## 默认受众与口吻

- 技术文章面向具备基础知识的开发者。
- AI 创作文章面向已经使用过相关工具的创作者。
- 默认采用专业自然的技术作者口吻，克制、直接、有判断。判断应交代依据和取舍，不靠反复写“我认为”制造作者感。
- 保留用户材料中真实的经验、偏好和有用细节；有作者样稿时匹配其节奏和措辞，不把样稿中的事实移植到新文章。
- 不讲行业常识、注册流程和基础按钮，除非它们会影响结果。
- 不写成产品宣传稿，不虚构经历、测试或数据。

## 工作流程

1. 识别用户目标、现有材料、文章类型和核心读者收益。
2. 区分新写、内容改写与仅调整文风。只有缺失信息会改变技术结论或用户要求的作者表达时，提出一个简短问题；其他情况沿用现有材料与默认口吻。
3. 新写、补充事实或核验疑点时，按研究规则检索官方文档、源码、标准、论文或原始发布内容。仅调文风时不扩展选题或新增事实。
4. 提炼一个核心结论。选题过大时，收窄到一个能完整讲清的问题。
5. 选择最小文章结构，删除不需要的章节。
6. 优先写结论、关键代码或完整提示词、实际结果、限制和取舍。
7. 核验事实、版本、模型、平台、参数、代码行为和引用。
8. 按自然写作规范重写有问题的段落，随后对照原稿检查事实、条件和受保护内容。去掉套话与机械节奏，保留有信息量的细节、真实的不确定性和技术术语。
9. 判断图片是否真正帮助解释、证明或比较内容，只为必要图片设置占位。
10. 需要排版交付时按主题规则选择预设，将参数展开为行内样式。先生成唯一的文章 HTML 片段，再由它生成 `wechat.md` 和 `wechat.html`。
11. 完整交付时生成四个文件，局部任务只更新请求产物；以质量清单的相关项检查。已有同源交付文件时保持其内容一致，全部修订合计最多两轮。
12. 需要文件交付时保存到当前工作区，返回摘要、文件链接和校验结果；仅文字润色则直接返回修改文本。

## 提示词处理

- 默认提供一个可直接复制的完整提示词。
- 用 `[角色设定]`、`[镜头运动]`、`[音乐风格]` 等明确占位符标记可替换变量。
- 标明适用工具、模型和用途；存在版本差异时简短说明。
- 只解释影响结果的关键变量，不逐句拆解或复述提示词。
- 未实际测试时，明确写“依据资料整理”或“建议尝试”。
- 不把单次生成结果描述为稳定能力。

## 去 AI 味

- 按 [references/natural-writing.md](references/natural-writing.md) 处理标题、摘要、正文、图注和可选互动语，优先修正夸大、空泛解释、机械列点、刻意转折和重复结尾，不执行机械的禁词替换。
- 用明确的主体、动作、结果与限制写清信息；长短句按含义组织，不故意塞入口头禅、错别字、情绪或碎句。
- 文风润色不改代码、命令、配置、完整提示词、引文原话、链接目标或事实数据。不能把“未验证”“可能”改成确定结论，也不能把资料整理写成亲身实测。
- 文末停在最后一个有用的结果、限制或建议。仅在确有交流价值或用户要求时补一个具体问题，不固定总结、升华或邀请留言。
- 重写和自检在内部完成，默认只交付最终成稿与既有文件，不附“AI 痕迹分析”、中间稿或检测分数。

## 主题与阅读兼容

- 内置极简墨色、技术蓝、松针绿、暖砂棕、朱砂红、鸢尾紫 6 款主题，具体参数与选择规则见 [references/themes.md](references/themes.md)。用户可指定名称；未指定时按文章类型选择，无法判断时使用技术蓝，不为选主题反复询问。
- 深浅色指读者手机微信的阅读模式。同一份文章适配两种环境，不生成两套正文，不要求读者手动切换文章配色。
- 正文、标题、链接及非代码组件使用透明背景与继承文字色。主题色用于边线，层级同时通过字号、粗细和间距表达。
- 所有代码块和提示词块圆角默认 2px，上限 2px，不随主题增大；保留原始换行、空格与缩进；单行内容不自动折行，长行只在块内水平滚动，不撑宽页面。使用排版规范中的完整组件，不将内容嵌入装饰元素。
- 预览页提供跟随系统、浅色、深色阅读检查；切换仅改变预览环境，不修改文章片段或复制配色。浏览器预览不等于微信真机验证，交付时分别说明已检查和未检查的范围。

## 图片处理

- 默认不自动生成图片，不声称已经上传到微信公众号素材库。
- 用户提供图片时，优先使用现有素材，并建议插入位置、裁剪比例和图片说明。
- 技术截图、效果对比和生成结果必须使用真实素材。
- AI 生成图片只用于封面或装饰插图，不代替事实证据。
- 使用网络图片时，标明来源并提示授权与转载风险。
- 没有必要配图时，不输出图片占位或配图清单。

正文统一使用可见占位：

```text
【配图 01｜用途｜建议比例｜替换为公众号素材库图片】
```

保持 Markdown 原稿、HTML 源码、预览页和配图清单的编号与位置一致。

## 默认交付

完整公众号文章通过质量检查后，默认保存到当前工作区的 `微信公众号文章/YYYY-MM-DD-短标题/`；片段修改与文字润色不自动创建以下四文件：

- `article.md`：3 个标题候选、60-100 字摘要、Markdown 正文和参考资料
- `wechat.md`：简短说明和一个包含完整文章片段的 `html` 代码块
- `wechat.html`：可独立打开的排版预览页，提供“复制到公众号”按钮
- `assets.md`：封面图提示词、必要的配图清单和素材库替换说明

`wechat.md` 与 `wechat.html` 必须来自同一个文章 HTML 片段，不得分别改写。正文样式全部使用行内 CSS，复制内容不得包含预览页按钮、说明或脚本。

保存成功后，只返回简短摘要、四个可点击文件链接和校验结果，不在对话中重复全文。具体命名、HTML 结构、复制逻辑、冲突处理和失败回退遵循 [references/wechat-formatting.md](references/wechat-formatting.md)。

不要输出写作过程、长篇资料综述或逐条写作解释。用户指定交付范围或路径时，以用户要求为准。

## 无法确认时

- 来源冲突时，优先采用最新一手资料，并简短指出差异。
- 无法确认版本、行为或授权时，明确标记，不猜测补齐。
- 无法运行示例时，只说明静态检查结果，不宣称已经验证。
- 当前工作区不可写时，不得改存到 Skill 安装目录。改为在对话中输出完整交付内容，并明确说明未保存。
- 两轮后仍缺少关键资料时，列出缺口并停止扩写。
