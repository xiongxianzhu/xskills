# 版本与平台适配

核实日期：2026-11-17。下列数字是所列官方页面在该日期的资料快照，不代表所有即梦、豆包、小云雀、第三方入口或后续模型都相同。

## 能力基线

| 模型 / 入口范围 | 已核实能力 | 对分镜的影响 |
| --- | --- | --- |
| Seedance 2.0，官方模型介绍 | 文本、图片、音频、视频参考；多镜头音视频；视频编辑和延长 [1] | 可写复杂运动和组合运镜；“只能慢动作”不是能力限制 |
| 火山方舟 2.0 系列 | 单次输出 4–15 秒，整数秒；支持自动时长 [2][3] | 固定成片时长时明确计划值；30 秒作品通常需分段 |
| 火山方舟 2.5 系列 | 单次输出 4–30 秒；编辑模式保留源片时长 [3][4] | 确认入口后才采用更长单段，不把 2.5 能力下放给 2.0 |
| 火山方舟全模态参考数量 | 2.0 系列：9 图 / 3 视频 / 3 音频，共 15；2.5：30 / 10 / 10，共 50；2.5 flash：10 / 5 / 5，共 20 [4] | 分别核验各模态和总量；入口可能更严格，旧的“统一最多 12 个”不能当通则 |
| 火山方舟音频参考 | 2.0 系列需搭配图或视频；2.5 支持仅音频参考 [4] | 只有音频时先确认模式，不补造图片标签 |
| 火山方舟画幅 | 包含 16:9、9:16、1:1、4:3、3:4、21:9；部分模式用 adaptive [2][3][4] | 横竖屏是常用交付比例，不是仅有选项 |

素材时长、大小、分辨率和格式限制按入口另查；不能把“输出最长 15 秒”解释成“输入视频总长 15 秒”。不根据模型名称猜测账号可用模式、资费或额度。

## 区分任务模式

| 类型 | 提示词必须说清 | 注意 |
| --- | --- | --- |
| 文本 / 参考生成新片 | 新片内容、每份参考仅控制什么 | 参考运镜不等于编辑原视频 |
| 首帧 / 首尾帧生成 | 首态、尾态、两端间的动作路径 | 在入口设置对应角色；普通参考标签不等于首尾帧参数 |
| 视频延长 | 源视频、向前或向后、衔接状态、新增事件 | 核实面板时长表示新增长度还是输出总长；未核实前只写制作意图 |
| 视频编辑 | 源视频、位置 / 时间区间、修改项、不变量 | 只改服装时不重写剧情与机位；输出时长可能无法另选 |

已确认使用火山方舟 2.5 API 时：首帧 / 首尾帧及延长要求 `ratio=adaptive`；编辑还要求 `duration=-1`，源视频为 4–30 秒 [4]。这是接口交接信息，不写进影视画面提示词，也不由本技能执行请求。

## 区分约束性质

| 性质 | 示例 | 处理 |
| --- | --- | --- |
| 已核实平台约束 | 版本的时长、素材数量、模式参数 | 附版本、入口、来源；用户提供的实际界面限制优先核实 |
| 用户要求 | 竖屏、共 30 秒、保留对白、全文 1000 字内 | 作为验收条件；冲突需解释，不偷偷覆盖 |
| 创作建议 | 一个主导运镜、精简参考、默认每段 2000 字符 | 可按目的调整，不冒充官方禁令或准确率结论 |

时间区间、镜号、`【声音】` 等是自然语言组织方式，不是严格执行的协议。官方 2.0 教程本身包含分秒段提示词 [2]；没有依据将时间码一概禁止。最终切点和精确卡点需要检查成片并剪辑。

`@图片1` / `@视频1` / `@音频1` 是可读绑定示例；官方不同入口也会展示 `图片1` 或 `@image1`。实际平台标签、素材顺序或 API 的 `content.role` 才决定绑定，不机械转换或杜撰专用标签。

## 更新与核实失败

1. 先确认模型和入口；“2.0+”不自动解释为“当前最新版本”。
2. 优先查实际入口帮助页和对应版本文档，只核实影响本次方案的限制并记日期。
3. 来源冲突时区分版本、模式、更新日期与入口，不拼凑参数。
4. 不能查最新资料时声明采用已核实基线，继续可移植分镜；暂停依赖未证实能力的部分。
5. 不保证“8K”“无水印”等提示词能改变导出规格或平台标识，按实际设置交接。
