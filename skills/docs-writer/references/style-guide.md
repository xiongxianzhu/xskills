# 风格指南（style-guide）

文档校对清单。按本文件逐项过，可消除大部分可读性问题。原则见 [SKILL.md 五原则](../SKILL.md)。

## 语态与人称

| 场景 | 用 | 例 |
| --- | --- | --- |
| 直接称呼读者 | **你** / you | "运行 `filesort .` 查看结果" |
| 共同动作 | **我们** / we | "我们先安装依赖" |
| 客观陈述 | 主动 + 现在时 | "该函数返回字符串" |
| 观点性引导 | 可用 **我** / I | 谨慎使用，仅限主观建议 |

**避免**：被动语态连串。"文件被扫描后被排序" → "扫描文件并排序"。

## 格式约定

| 元素 | 格式 | 例 |
| --- | --- | --- |
| 命令、变量、文件名 | `行内代码` | `pip install`、`config.yaml` |
| UI 元素、按钮、菜单项 | **加粗** | **运行** 按钮、**Settings** |
| 占位符 | 大写 | `API_KEY`、`USERNAME` |
| 强调 | *斜体*（克制） | 关键术语首次出现 |
| 代码块 | 带语言标签 | ` ```bash `、` ```python ` |

## README 头部与徽章

本节仅在目标文件名为 `README.md` 时默认应用。目标是让项目身份和可信状态快速可见，同时避免为了视觉效果编造信息。

### Shields.io 识别与样式统一

图片 URL 包含 `img.shields.io` 时，将其视为 Shields.io 徽章。同一 README 中的全部 Shields.io 徽章统一使用 `style=for-the-badge`：

| 原 URL 状态 | 处理方式 |
| --- | --- |
| 没有查询参数 | 追加 `?style=for-the-badge` |
| 有查询参数但没有 `style` | 追加 `&style=for-the-badge` |
| 已有任意 `style` 值 | 只把该值替换为 `for-the-badge` |

保留徽章颜色、Logo、标签、链接目标和其他查询参数。不要修改非 Shields.io 图片、自托管徽章、Logo 或截图。

### 缺少徽章时

README 没有 Shields.io 徽章时，默认添加 2–4 枚有事实依据的徽章。按以下优先级选择：

1. 从包配置、依赖清单或源码确定的主要技术栈与运行时。
2. 从 `LICENSE` 或包元数据确定的许可证。
3. 从真实存在的工作流确定的 CI 状态。
4. 从明确的包名和发布源确定的版本。

不根据猜测添加构建通过、最新版、覆盖率或下载量。信息不足时减少徽章数量；连项目技术栈都无法可靠确定时，先向用户确认。

### 居中结构

使用下列结构居中 README 的顶部视觉区域：

```markdown
<div align="center">

# 项目名称

一句话价值主张。

[![Python](https://img.shields.io/badge/Python-3.11%2B-3776AB?logo=python&logoColor=white&style=for-the-badge)](https://www.python.org/)

</div>
```

- 将第一个 H1 视为项目主标题，正文中的其他标题不参与居中。
- 已有 `<div align="center">` 时复用，避免嵌套。
- 已有 Logo、简介或顶部导航时保留，并纳入同一顶部视觉区域。
- 在第一个 H2 之前结束居中容器，正文保持左对齐。
- 不重复创建标题、Logo 或语义相同的徽章。
- 修改已有 README 时，尽量只调整顶部区域和 Shields.io URL。

## 代码示例规范

每个示例必须满足：

1. **可运行**：完整、含必要 import 与上下文，读者复制即可跑。
2. **有输出**：紧接 `# Output:` 或独立代码块展示预期结果。
3. **有注释**：仅注释非显然逻辑；显而易见的代码不加注释。
4. **最新**：与当前版本一致；版本号、参数名、API 签名不要过时。

```python
def greet(name: str) -> str:
    """简短说明。"""
    return f"Hello, {name}"

# 示例用法
print(greet("world"))
# Output: Hello, world
```

## 术语处理

- **首次出现定义**：技术术语第一次提到时用一句话解释或括注。
- **一致性**：同一概念全文用同一个词，避免"函数/方法/过程"混用。
- **缩写**：首次 `完整词（ABBR）`，后续直接 `ABBR`。

## 常见反模式（校对清单）

写作与审校时逐条排查：

- [ ] **开头堆功能**：未先说价值主张，直接列特性
- [ ] **有描述无示例**：关键概念只有文字，没有可运行代码
- [ ] **被动语态连串**：连续多句"被…"结构
- [ ] **死板套模板**：机械照搬结构，不顾读者实际需要
- [ ] **超长句子**：单句超过 25 词
- [ ] **未定义术语**：堆砌专业词无解释
- [ ] **过时代码**：示例与当前版本不匹配
- [ ] **缺错误处理**：只讲成功路径，不讲常见失败
- [ ] **层级混乱**：H2 直接连 H4，或同级标题层级不一致
- [ ] **链接失效**：内部锚点、外部 URL、相对路径未验证
- [ ] **README 头部未居中**：项目主标题、简介和徽章区没有形成统一的居中区域
- [ ] **Shields 样式混用**：同一 README 中仍存在非 `for-the-badge` 的 Shields.io 徽章
- [ ] **徽章状态失真**：许可证、CI、版本、覆盖率或下载量缺少可靠依据
- [ ] **破坏复杂头部**：新增嵌套容器、重复标题、重复徽章，或误改 Logo 与导航

## 句长与密度

- 单句 ≤ 25 词（中文 ≤ 40 字）
- 一段一个主旨
- 列表项 ≤ 2 行，超长则拆子项或转表格
