# 技能质量标准

本标准用于新增和评审 Agent Skill。自动校验负责格式与可解析性，人工评审负责内容是否真正可用。

## 最低要求

### 1. 触发准确

- `description` 清楚说明适用任务、典型输入和必要触发词。
- 不用“万能”“任何场景”等过宽表述。
- 与仓库现有 Skill 重叠时，说明边界或合并理由。

### 2. 流程可执行

- 指令使用明确动作，写清顺序、条件分支和停止条件。
- 必要输入缺失时，说明应询问、推断还是停止。
- 不依赖智能体猜测未声明的文件、工具或上下文。

### 3. 输出可验收

- 写明输出格式、保存位置或交付方式。
- 给出能判断成功与否的检查项。
- 示例只展示关键行为，不堆积同类内容。

### 4. 内容精简

- `SKILL.md` 只保留每次执行都需要的核心流程。
- 长规范、模板和案例按需放入 `references/`。
- 只为可重复且需要确定性的逻辑新增脚本。

### 5. 安全可靠

- 对删除、覆盖、发布、付费或外部写入等操作设置确认边界。
- 不要求提交密钥、令牌、个人数据或缓存。
- 涉及时效性或高风险信息时，要求核验一手来源并标明限制。

## 推荐质量

- 说明何时不应触发该 Skill，以及应改用什么流程。
- 对常见失败提供简短恢复方式。
- 将固定模板、资源或脚本复用起来，避免每次重新生成。
- 修改脚本时提供至少一个代表性测试或可重复示例。
- 让不同智能体在相同输入下得到结构一致、差异可解释的结果。

## 自动校验范围

仓库校验脚本会递归检查全部 `skills/**/SKILL.md`：

- YAML frontmatter 位于文件开头且可解析。
- `name`、`description` 是非空字符串。
- `name` 与 Skill 目录名一致且全仓库唯一。
- Skill 与分类目录使用规定的层级和小写 kebab-case；`_template` 是唯一内部例外。
- 相对文件链接、当前文件锚点和跨 Markdown 文件锚点存在。

外部网址不会发起网络校验，来源质量由人工评审。

## 不接受的模式

- 只有角色设定或宽泛口号，没有可执行流程。
- 把一次性提示词包装成 Skill，却没有稳定工作流或复用价值。
- 在 `SKILL.md` 重复粘贴大量官方文档、案例或背景知识。
- 链接到不存在的本地文件，或保留未完成标记作为正式内容。
- 未说明风险就执行不可逆操作或对外发布。
