# 通用角色三视图提示词 Skill 设计

## 1. 目标

新增 `character-turnaround-sheet` Skill，将文字描述、角色卡、小说人物设定或参考图片整理为一段可直接复制的中文图像生成提示词，用于制作标准化角色设定板。

成品固定为 16:9 横版，按“上半身特写 → 全身正视图 → 全身侧视图 → 全身背视图”的顺序展示同一角色。Skill 只生成提示词，不直接生成图片。

## 2. 定位与边界

### 2.1 适用范围

- 单次处理一名人类或类人角色。
- 支持人类、精灵、兽人、机器人、改造人和拟人动物等具有稳定直立躯干结构的角色。
- 支持文字描述、角色卡、小说人物设定和参考图片。
- 支持写实、半写实、3D、二次元、卡通、游戏、影视和科幻等视觉风格。
- 用户指定风格时严格继承；存在参考图时保持参考图的媒介与画风；两者都没有时，默认使用高端半写实 3D 角色概念设计。

### 2.2 不适用范围

- 四足、蛇形、无定形或无法采用标准直立姿态的生物。
- 多角色同板、武器展示板、独立道具展示板。
- 黑金版式、多细节栏目或包含文字说明的信息型角色设定集。
- 直接生成图片。

古风美女、古风男主和固定 3D 国漫任务可继续使用现有专项 Skill。用户强调通用画风、参考图复刻或非古风类人角色时，优先使用本 Skill。

## 3. 文件结构

```text
skills/ai-drama/character-turnaround-sheet/
├── SKILL.md
├── references/
│   ├── identity-lock.md
│   └── prompt-template.md
└── evals/
    └── evals.json
```

- `SKILL.md`：触发边界、输入解析、冲突消解、执行步骤、停止条件和输出契约。
- `references/identity-lock.md`：参考图与角色资料的特征提取、一致性锁定和不可见区域补全规则。
- `references/prompt-template.md`：四栏版式、姿态、镜头、光影、质量和禁止项模板。
- `evals/evals.json`：三个代表性测试任务及可客观检查的期望结果。

不新增脚本。提示词创作包含主观视觉判断，使用脚本机械拼接会降低自然度，且没有足够的确定性收益。

## 4. 输入解析与冲突消解

### 4.1 输入来源

Skill 从以下来源提取角色资料：

1. 用户本次明确提出的保留或修改要求。
2. 参考图片中可见的角色特征。
3. 角色卡、小说人物设定或其他文字资料。
4. 根据已有设计语言作出的保守推断。

发生冲突时严格按照以上顺序取舍。用户本次明确要求修改的特征优先于参考图片；未要求修改的可见特征继续由参考图片锁定。

### 4.2 内部身份锁定

生成提示词前，在内部锁定以下信息，但不向用户展示中间清单：

- 身份、性别或物种、年龄段、身高与体型比例。
- 脸型、五官比例、肤色、瞳色及稳定识别标记。
- 发色、发量、发际线、刘海、主体发型及后部结构。
- 服装层级、版型、材质、颜色、纹样和闭合方式。
- 固定配饰的名称、数量、尺寸、方向及佩戴位置。
- 不对称结构所在的身体侧别，避免在不同视图中镜像翻转。

### 4.3 缺失信息

- 只有角色身份、性别或物种、核心视觉方向等决定性信息不足时，才向用户提出一个关键问题。
- 普通细节缺失时直接保守补全，不逐项询问。
- 不可见背部延续正面材质、配色和结构逻辑，采用对称、低复杂度设计，不新增复杂纹样、开口或大型装饰。
- 参考图片无法读取或角色被严重遮挡时，要求用户重新提供清晰图片。
- 输入包含多个角色时，要求用户指定本次处理的一名角色。

## 5. 固定画面规范

### 5.1 画布与布局

- 16:9 横版，8K 超高清，高精度角色设定板。
- 纯白、无缝、均匀、无纹理背景，不出现地平线、场景、装饰框或环境物体。
- 从左到右严格排列：上半身特写、全身正视图、全身侧视图、全身背视图。
- 上半身特写约占画面宽度 28%，三个全身视图各约占 24%。
- 四栏保留均匀留白，人物不得重叠、越界或裁切。

### 5.2 镜头与姿态

- 上半身特写采用正面朝向，展示头部、肩部、胸部上方和关键上装细节。
- 三个全身视图使用相同镜头高度、焦距、人物尺度和自然 A-Pose。
- 角色直立，双臂自然下垂并与躯干略微分开，双脚平行稳定站立。
- 正视图严格 0°、侧视图严格 90°、背视图严格 180°。
- 三张全身图的头顶线、肩线、胯线和脚底线对应一致。

### 5.3 跨视图一致性

- 四栏表现同一角色、同一年龄、同一体型和同一服装版本。
- 脸型、五官比例、肤色、发色、发量、发际线和发型结构统一。
- 服装层级、剪裁、材质、纹样、颜色和闭合方式统一。
- 固定配饰的数量、大小、方向和佩戴位置统一。
- 不镜像改变不对称设计，不在侧视或背视图新增未定义装饰。

“100% 一致”作为提示词中的强约束目标，但 Skill 不宣称可以控制图像模型最终生成结果达到数学意义上的完全一致。

### 5.4 光影与画质

- 使用中性影视级三点布光：柔和主光、低强度补光和克制轮廓光。
- 四栏保持相同色温、曝光、阴影方向和材质表现。
- 强调清晰轮廓、真实材质、高精度纹理和完整边缘。
- 避免戏剧性逆光、彩色环境光、硬阴影和过度景深。

### 5.5 禁止项

- 武器、手持物和独立陈列道具。
- Logo、水印和标尺。
- 额外角色、重复肢体、人物重叠、身体裁切和画面越界。
- 场景元素、装饰背景和干扰结构对照的动态姿势。
- Midjourney、即梦或其他平台专用参数。

固定在身体或服装上的耳饰、徽章、腰带、护甲组件等配饰可以保留，但必须跨视图锁定位置、方向、数量和材质。

## 6. 执行流程

1. 判断任务是否属于单一人类或类人角色的标准三视图设定板。
2. 识别输入来源、本次修改要求和目标视觉风格。
3. 按既定优先级合并信息并消解冲突。
4. 读取 `references/identity-lock.md`，建立内部身份锁定清单。
5. 对遮挡或不可见区域执行保守补全。
6. 读取 `references/prompt-template.md`，将角色信息写入固定四栏模板。
7. 检查版式、姿态、跨视图一致性、光影、禁用项和输出格式。
8. 只输出一个包含完整中文提示词的 Markdown 代码块。

## 7. 输出契约

- 最终响应只包含一个中文 Markdown 代码块。
- 代码块内是一段完整、连续、平台无关且可直接复制的提示词。
- 不输出分析、角色锁定清单、变量表、解释、备选版本或独立负面提示词。
- 所有禁止项使用自然语言整合进主提示词。
- 当必须补充决定性信息或任务超出支持范围时，先提出一个关键问题或简短说明限制，不输出不完整提示词。

## 8. 测试与验收

### 8.1 代表性测试

1. 纯文字现代人类角色：验证缺失细节补全、默认画风和固定版式。
2. 参考图改造角色：验证参考特征继承和当前修改指令优先级。
3. 类人非人角色：验证机器人、精灵或拟人角色不会被错误改成人类模板。

### 8.2 客观检查项

- 输出只有一个代码块。
- 提示词包含 16:9、纯白无缝背景、8K 和影视级三点布光。
- 四栏顺序准确且包含 28%/24% 的版式关系。
- 包含自然 A-Pose、0°/90°/180°和全身对齐要求。
- 包含身份、服装、发型和配饰的跨视图锁定。
- 明确禁止武器、道具、水印、裁切、重叠和额外角色，但不禁止文字、标题或视图标签。
- 不包含特定图像平台参数。

视觉审美、描述自然度和角色设计合理性由人工评审，不使用机械指标冒充主观质量判断。

## 9. 仓库同步与验证

新增 Skill 后同步更新：

- `skills/ai-drama/README.md` 的角色设定索引与数量。
- 根目录 `README.md` 的 AI 漫剧 Skill 数量。
- `llms.txt` 的 Skill 入口、分类说明和相关计数。

实施完成后执行：

```bash
python -m unittest discover -s tests -v
python scripts/validate_skills.py
git diff --check
```

同时检查 frontmatter、目录名和 `name` 一致，所有相对链接存在，新增文件不含未完成标记或占位说明。
