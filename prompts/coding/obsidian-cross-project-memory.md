# Obsidian 跨项目长期记忆

## 使用方式

**方式 A — 会话开头设定**  
在开始工作前先发送下方 Prompt，让 Agent 建立「先检索记忆、后执行任务、完成回写」的工作模式。

**方式 B — 配合 Obsidian MCP / 文件访问**  
Agent 需能读写 Obsidian 库（本地路径或 MCP 工具）才能发挥完整效果；无文件访问能力时，本提示词只保留「只保留有价值信息」的约束意义。

**方式 C — Cursor 引用**  
在对话中 `@prompts/coding/obsidian-cross-project-memory.md`，再描述你的任务。

## Prompt

```
请将当前 Obsidian 知识库作为我的跨项目长期记忆系统，为所有项目建立统一索引和知识结构。持续整理并维护项目背景、长期偏好、关键决策、已完成内容、当前进度、失败方案、踩坑记录、技术方案和下一步计划。
每次开始新任务前，先检索 Obsidian 中与当前任务相关的笔记，补充必要上下文后再执行任务；任务完成后，将新增的结论、重要决策、代码变更记录和项目进度同步更新到对应文档。
只保留未来有价值的信息，避免记录无关对话、重复内容或临时信息；不要保存密码、api Key、token 等敏感信息。
```

## 示例

**你发送：**

```
（先发送上方 Prompt）

帮我继续开发病历复印项目的退款模块。
```

**Agent 应先检索再动手：**

- 检索库中「病历复印」「退款」相关笔记，恢复项目背景与进度
- 读取上次的踩坑记录（如支付宝证书路径问题），避免重蹈覆辙
- 任务完成后，把本次新增决策（如「退款状态轮询间隔定为 5 分钟」）和代码变更回写到对应文档

## 维护要点

- 记忆分三类写入：**项目档案**（背景/进度/下一步）、**决策日志**（关键决策与理由）、**经验库**（失败方案/踩坑记录）
- 只沉淀「未来有价值」的信息，闲聊、临时调试输出不入库
- 敏感信息（密码 / API Key / token）一律不写入

## 升级路径

若此工作流需要**自动触发**（任务开始自动检索、结束自动回写），可评估做成 Skill 并接入 Obsidian MCP；先做 [Loop 就绪度自检](../meta/loop-readiness-check.md)。
